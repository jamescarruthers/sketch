# Sketch — specification

A web-based CAD sketcher that behaves like the Fusion Sketch environment documented in `reference/`.
`reference/files/*.htm` is the source of truth for behaviour. This file distils it and fixes the
engineering contract between modules. When this file is silent, read the reference page.

Tags: **[ref]** = stated in the reference docs. **[fusion]** = standard Fusion behaviour not in the
reference. **[adapt]** = deliberate adaptation to a 2D, browser-only app. **[user]** = decided by the
user, beyond the reference.

---

## 1. Stack

| Concern | Choice |
|---|---|
| App | TypeScript (strict), Vite, no UI framework (plain DOM modules) |
| Rendering | Canvas 2D, devicePixelRatio aware |
| Constraint solver | Rust crate `solver/` compiled with wasm-pack (`--target web`) to `src/solver/pkg/`, wrapping **`kcl-ezpz` 0.2.18 as an unmodified crates.io dependency** |
| Unit tests | `vitest` (TS), `cargo test` (Rust) |
| E2E | Playwright (chromium), `e2e/` |
| Text outlines | `opentype.js` + bundled OFL fonts from `@fontsource/*` |

Scripts in `package.json`: `npm run wasm`, `npm run dev`, `npm run build` (wasm + tsc + vite),
`npm test`, `npm run e2e`. `wasm-opt` is not installed, so set
`[package.metadata.wasm-pack.profile.release] wasm-opt = false`.

`node_modules/`, `dist/`, `solver/target/`, `src/solver/pkg/`, `test-results/`, `playwright-report/`
are gitignored. No `any` in public module APIs. Code comments are sparing: explain why, not what.

## 3. Data model (`src/model/types.ts`, verbatim contract)

All coordinates are in **millimetres** in sketch space, Y up. Angles in radians internally.

```ts
export type Id = string;
export interface Vec2 { x: number; y: number }
export type LineType = 'normal' | 'construction' | 'centerline';

/** Every position in a sketch is a Point. Curves reference points by id. */
export interface Point {
  id: Id; x: number; y: number;
  /** Created by the Point tool: survives deletion of curves, is drawn and exported as a point. */
  explicit?: boolean;
  /** Set by Fix/UnFix. */
  fixed?: boolean;
  /** Owning curve, if any (centres, endpoints, fit points, handles). */
  owner?: Id;
}

interface CurveBase {
  id: Id;
  lineType: LineType;
  fixed?: boolean;
  /** Projected geometry: locked, purple. Holds its source for associativity. */
  projected?: { sketchId: Id; curveId: Id } | { origin: 'x' | 'y' };
  /** Generated by a Feature (offset): regenerated after solve, immovable in the solver. */
  derivedFrom?: Id;
}
export interface Line extends CurveBase { type: 'line'; a: Id; b: Id }
export interface Circle extends CurveBase { type: 'circle'; c: Id; r: number }
/** Always counter-clockwise from a to b. Radius is |c-a|. */
export interface Arc extends CurveBase { type: 'arc'; c: Id; a: Id; b: Id }
/** major, minor are the axis end points. Solver keeps c-major perpendicular to c-minor. */
export interface Ellipse extends CurveBase { type: 'ellipse'; c: Id; major: Id; minor: Id }
/** Result of trimming an ellipse. Counter-clockwise from a to b. */
export interface EllipticalArc extends CurveBase { type: 'ellipticalArc'; c: Id; major: Id; minor: Id; a: Id; b: Id }
/** Interpolating cubic spline (chord-length parameterised, natural ends unless a handle is active). */
export interface FitSpline extends CurveBase {
  type: 'fitSpline'; pts: Id[]; closed: boolean;
  /** Tangent handle point per fit point, or null when inactive. */
  handles: (Id | null)[];
}
/** Clamped uniform B-spline. */
export interface ControlSpline extends CurveBase { type: 'controlSpline'; pts: Id[]; degree: 3 | 5 }
/** Rational quadratic: a, b end points, v vertex, rho in (0,1). */
export interface Conic extends CurveBase { type: 'conic'; a: Id; b: Id; v: Id; rho: number }
export interface TextEntity extends CurveBase {
  type: 'text'; mode: 'frame' | 'path';
  text: string; font: string; bold: boolean; italic: boolean;
  height: number; spacing: number; // percent
  flipH: boolean; flipV: boolean;
  halign: 'left' | 'center' | 'right'; valign: 'top' | 'middle' | 'bottom';
  /** frame: 4 corner points of the constrained frame rectangle (ccw from bottom-left). */
  frame?: [Id, Id, Id, Id];
  /** path: curve followed. */
  path?: Id; above?: boolean; fitToPath?: boolean;
}
export type Curve = Line | Circle | Arc | Ellipse | EllipticalArc | FitSpline | ControlSpline | Conic | TextEntity;

export type ConstraintType =
  | 'coincident'      // [point, point] or [point, curve]
  | 'horizontal'      // [line] or [point, point]
  | 'vertical'        // [line] or [point, point]
  | 'parallel'        // [line, line]
  | 'perpendicular'   // [line, line] or [line, arc/circle] (radial)
  | 'tangent'         // [curve, curve]
  | 'equal'           // [line, line] lengths or [circle/arc, circle/arc] radii
  | 'midpoint'        // [point, line/arc]
  | 'concentric'      // [circle/arc/ellipse, circle/arc/ellipse]
  | 'collinear'       // [line, line]
  | 'symmetric'       // [a, b, axisLine]: a,b are points or matching curves
  | 'curvature'       // [spline, curve]
  | 'offsetCopy'      // [p, q]; q = p + {dx,dy}. Rectangular patterns.
  | 'rotatedCopy';    // [c, p, q]; q = p rotated about c by angle. Circular patterns.
export interface Constraint {
  id: Id; type: ConstraintType; refs: Id[];
  dx?: number; dy?: number; angle?: number;
  /** Which end/side, chosen once from geometry at creation, so solves don't flip. */
  variant?: number;
  /** Feature that owns this constraint; hidden from glyphs, removed with the feature. */
  feature?: Id;
}

export type DimensionKind =
  | 'distance'    // [p, q] aligned
  | 'horizontal'  // [p, q]
  | 'vertical'    // [p, q]
  | 'pointLine'   // [p, line]
  | 'lineLine'    // [line, line], parallel lines
  | 'angle'       // [line, line]
  | 'radius'      // [arc/circle]
  | 'diameter'    // [arc/circle]; also [centerline, point] revolve diameter
  | 'arcLength'   // [arc]
  | 'ellipseAxis'; // [ellipse, 'major'|'minor' via variant]
export interface Dimension {
  id: Id; kind: DimensionKind; refs: Id[];
  name: string;         // d1, d2, ... unique per document, never used twice
  expression: string;   // "25.4 mm", "d1 * 2"
  value: number;        // resolved, mm or radians
  driving: boolean;     // false = Driven: shown "(12.00)", read only, not sent to solver
  label: Vec2;          // sketch-space label position
  variant?: number;     // e.g. axis of ellipse, which quadrant of an angle
  feature?: Id;
}

export type Feature =
  | { id: Id; type: 'rectPattern'; sources: Id[]; dirs: [Vec2, Vec2 | null]; distanceType: 'extent' | 'spacing';
      quantity: [number, number]; distance: [number, number]; direction: ['one' | 'symmetric', 'one' | 'symmetric'];
      suppressed: string[]; instances: Record<string, Id[]> }
  | { id: Id; type: 'circPattern'; sources: Id[]; center: Id; spacing: 'full' | 'angle' | 'symmetric';
      angle: number; quantity: number; suppressed: string[]; instances: Record<string, Id[]> }
  | { id: Id; type: 'offset'; sources: Id[]; distance: number; side: 1 | -1; dimension: Id | null; outputs: Id[] }
  | { id: Id; type: 'mirror'; axis: Id; pairs: [Id, Id][] };

export type Plane = 'XY' | 'YZ' | 'ZX';
export interface Vec3 { x: number; y: number; z: number }
/** Origin and orthonormal in-plane axes, in mm; normal u x v. A sketch point (x, y) is at o + x u + y v. */
export interface Frame { o: Vec3; u: Vec3; v: Vec3 }
export interface Sketch {
  id: Id; name: string; frame: Frame; visible: boolean;
  points: Record<Id, Point>;
  curves: Record<Id, Curve>;
  constraints: Record<Id, Constraint>;
  dimensions: Record<Id, Dimension>;
  features: Record<Id, Feature>;
}
export interface UserParameter { name: string; expression: string; value: number; comment: string; unit: 'mm' | 'deg' | '' }
export interface Design {
  version: 1; name: string;
  sketches: Record<Id, Sketch>;
  order: Id[];
  parameters: UserParameter[];
  units: 'mm' | 'cm' | 'm' | 'in' | 'ft';
  nextId: number;
}
```

Every sketch has a `frame` (design version 3). The origin planes are frames too (`PLANE_FRAMES` in
`src/model/frames.ts`): XY is u = X, v = Y (normal +Z); YZ is u = Y, v = Z (+X); ZX is u = Z, v = X (+Y).
A version 1 or 2 file names a plane instead, and opens with that plane's frame. Frames are tidied as they
are made and read: a component within 1e-12 of 0 or ±1 is exactly that, and the axes are made unit and square.

`ORIGIN` is the reserved id `origin` (a fixed point at 0,0), and `axis-x`, `axis-y` are reserved,
fixed infinite construction lines. In a sketch they are its own: through its origin, along u and v. They exist in every sketch without being stored, and constraints
and dimensions may reference them.

## 4. Solver contract

`solver/` exposes one wasm function, `solve(json: string) -> string`.

**Input**
```jsonc
{
  "points": [{ "id": "p1", "x": 0, "y": 0, "fixed": false }],
  "curves": [
    { "id": "l1", "type": "line", "a": "p1", "b": "p2" },
    { "id": "c1", "type": "circle", "c": "p3", "r": 10 },
    { "id": "a1", "type": "arc", "c": "p4", "a": "p5", "b": "p6" },
    { "id": "e1", "type": "ellipse", "c": "p7", "major": "p8", "minor": "p9" },
    { "id": "s1", "type": "spline", "pts": ["p10", "p11"], "degree": 3, "fit": true,
      "handles": [null, "p12"], "samples": [[0, 0], [1, 1]] }
  ],
  "constraints": [{ "id": "k1", "type": "coincident", "refs": ["p1", "p2"], "variant": 0 }],
  "dimensions": [{ "id": "d1", "kind": "distance", "refs": ["p1", "p2"], "value": 25.4, "variant": 0 }],
  "drag": [{ "point": "p2", "x": 12, "y": 5 }],   // low priority targets
  "hold": ["p1"],                                 // low priority: stay where you are
  "analyze": true,
  "branches": {                                   // what must not jump; empty for a drag
    "arcs": [["c", "a", "b"]],                    // centre and ends
    "loops": [["p1", "p2", "p3"]],                // corners of a closed loop of lines and arcs
    "bulges": [[{ "at": 1, "c": "p4", "ccw": true }]] // its arc edges: from corner `at` to the next, about `c`
  },
  "slack": 0.001,                                 // optional: how near met counts as met when asking
  "plain": false,                                 // optional: nothing but the rows, no size or length held
  "walls": [["p1", "p2"]]                         // optional: lines of closed profiles, by their ends
}
```

**Output**
```jsonc
{
  "ok": true,
  "points": { "p1": [0, 0] },
  "radii": { "c1": 10 },
  "unsatisfied": ["k1", "d1"],   // constraint or dimension ids
  "freePoints": ["p2"],          // only when analyze
  "freeCurves": ["c1"],          // only when analyze: curve has any free variable
  "dof": 4,                      // only when analyze
  "iterations": 7,
  "crossed": null,               // "arc" or "loop": a solution was turned down for jumping
  "kept": true,                  // every size, length and sweep the rows leave free stayed
  "resized": [],                 // curves whose free radius could not stay
  "error": null
}
```

Requirements:

- Reserved ids `origin`, `axis-x`, `axis-y` are built in.
- Union-find coincident point pairs so they share ezpz variables. This shrinks the system.
- Split into connected components and solve each independently, so one failure cannot corrupt
  unrelated geometry. A drag leaves out components it does not touch; a commit solves them all. Include only components touched by `drag`/`hold` when `analyze` is false and
  a component filter applies.
- Model arc and circle radius with a distance variable so tangent and equal work uniformly.
- Choose tangent/parallel/angle branches from `variant` or current geometry, never flip during a drag.
- **ezpz gaps, modelled with hidden helper geometry, no fork:** ellipse point-on and tangent via the
  two-circle construction; spline tangent via handle/first control leg; point-on-spline by outer
  iteration against the local tangent of `samples`, and when that leaves anything undone a second
  build with a hidden mix of the spline's nearby points, so the point can move the spline; control
  spline curvature with a line by collinearity of the first three control points, otherwise by outer
  iteration on the target offset of the third control point; fit spline curvature by the handle's
  length, or the next fit point's offset where the length cannot do it, the target always the other
  curve's real curvature at the joint. Document each in the crate.
- `dimension.value` for over-constraint testing is the caller's concern: the bridge exposes
  `wouldOverConstrain(doc, dim)`, implemented by solving with value and value+delta. If the perturbed
  system is unsatisfied, the dimension is redundant or conflicting.
- Must solve a 500-curve sketch drag step in under 16 ms in a release build (`analyze: false`).

`src/solver/bridge.ts` API:
```ts
export async function initSolver(): Promise<void>;
export interface SolveOptions { drag?: { point: Id; x: number; y: number }[]; hold?: Id[]; analyze?: boolean }
export interface SolveResult { ok: boolean; unsatisfied: Id[]; freePoints: Set<Id>; freeCurves: Set<Id>; dof: number; error?: string }
/** Mutates sketch point positions and radii on success. */
export function solveSketch(sketch: Sketch, opts?: SolveOptions): SolveResult;
export function wouldOverConstrain(sketch: Sketch, dim: Dimension): boolean;
```
After a successful solve, the bridge regenerates `derivedFrom` geometry (offset outputs).

**Seat and guard (`src/solver/bridge.ts`, `src/solver/seat.ts`).** Every solve goes through `solveSketch`. Outside a drag, a constraint the incoming geometry does not satisfy is new, or in conflict: before solving, the second object is moved rigidly to where the constraint holds, so length and size survive. Each constraint offers several such seats, tried against the real solver, because only the solver knows what the rest of the sketch allows. After any solve, a line, radius, arc span or ellipse axis that reached zero, or a point thrown far outside the sketch, means the solve is thrown out: geometry goes back to how it arrived and `refusal` says why. `App.commit` reverts the commit on a refusal and shows the reason.

**Bodies (`src/solver/bodies.ts`).** A commit starts by asking what it is about: every row the geometry does not meet, and what those rows name. From that and the sketch's graph (curves, coincidence classes, constraints, dimensions, expressions and features) it takes each piece that only a cut point joins to what the commit is about, or to anything fixed, projected or locked. The joint must be a curve's own point: a point riding on a curve does not carry the curve. Those bodies are left out of every solve of the commit through `SolveOptions.without`, and put back on their joints afterwards, unrotated. After that, `settlePieces` moves any piece whose joints all moved by one vector by that vector.

**Point on a spline.** A solve builds the point riding first, with no spline variable in its row. Only a drag of the point, a drag that stops short or a row left unmet goes on to a build where the point can pull. A row left unmet is first read along the curve, the rest held, since the riding row is a tangent line and misses what the curve reaches further on: the point is tried from each place the row crosses zero, nearest first. A commit there tries the spline's ends alone, interior points held, and takes that unless the ends go over three times as far as they would with the interior free. A sketch that was fine riding solves as it did. `dof` and the free lists always count the point against the spline. When only asking what the geometry satisfies, a point within the slack of the true curve is on it, whatever the chords between its samples say.

**Curvature at a spline end.** After a solve the real end curvature of a fit spline, or of a control spline matched to a fit spline, ellipse or conic, is compared with its target. A row that is met proves nothing, its constant having come from the last round. If it is off or cannot be read, the component keeps its input geometry and the constraint is unsatisfied. A handle in the hand keeps the cursor's length and the next fit point carries the curvature. With that point pinned the handle stays.

**Opening a file.** A sketch with a Curvature is solved as the file opens, before the history starts. If that moves a Curvature curve by 1e-6 mm or more, the solved sketch replaces the one in the file, one note names the sketches, and the design counts as unsaved. A reload still knows the file by what it held. Anything else opens clean and silent.

**Choosing a seat.** A seat that holds the first pick, keeps what it means to keep and leaves the rest alone wins, the one that sends least along first. Otherwise, for a constraint, every candidate is scored across the whole sketch: summed relative size change plus the furthest move as a share of the sketch's extent. The candidates are the seats, the unseated solve, the unseated solve without the holds, and a `plain` solve that holds nothing but the rows. The last two are tried only when the constraint's objects are in one joined body: between two bodies one can give way whole, at no cost in shape. Going against the holds counts for little if it takes under 0.4 of the travel of the best candidate that keeps them, within one body, and rules a candidate out otherwise. A sweep changed by more than 60 degrees or an undimensioned line under half its length marks a candidate failed: it is used only if there is no other, and a note goes with it. Every candidate must really meet the row, and turn no face over. A value edit does not come through here: it keeps its continuity by steps.

**Loops (`src/solver/faces.ts`).** `branches.loops` holds the bounded faces of the graph of lines and arcs, traced by heading at each joint, and `branches.bulges` their arc edges. A loop sharing an edge with another is its own face. Any other cycle is a sum of faces, so faces are enough. A loop is walked both ways and the counter-clockwise walk is the face; a bow tie whose lobes balance has no such walk and is taken as it is, since it crosses. Anything else that flat has no inside and is no face. Each is split at cut points and bridges first. A face's side is its true area: the corners' polygon plus each arc's segment, the same on both sides of the wasm boundary. A row that leaves a face with no side reports `crossed: "flat"`; one that puts it on the other side reports `"loop"`.

**Outlines.** Every face, splines and conics included, is flattened on a commit, and those that are simple as it begins are watched. A candidate that makes one run through itself has failed, as a wrecked shape has. A value tries a walk, then a plain walk, then a plain walk holding the lines that turned back to 1, 0.5 and 0.25 of their length, with a note if that works. If every answer tried crosses, the plain answer stands with a note. That is every answer tried, not every answer there is: the note can be untrue (OPEN-55). A drag does not come here. An outline that crosses as a commit begins is left out of `branches` and `outlines`: nothing guards it, a commit that asks for something goes through with a note while it stays crossed, and it can come out. A solve of a sketch as it stands asks for nothing and has no note.

**Walls.** On a value edit `walls` lists the lines of closed profiles. Once holding every span and wall together has failed, the solve tries two answers: all free spans, and as many walls on their lines as can stay, arc sweeps first and free lengths last. The wall answer is taken if it moves less and leaves no line under half of itself.

**Names.** `Design.names` is a counter for `d` and `p` names that only goes up, saved with the design. An old file starts past every name it shows, including one an expression asks for that nothing has. When a dimension or parameter goes by any route, each expression using it takes its last value, written exactly, in `keepLostValues`, and one note says so. An expression that dangles in a file opens, its label in the error colour, with a note naming it. Change Parameters refuses to delete a parameter in use, so that route never reaches this.

**Other layers in Change Parameters.** A dimension on a layer that is not active, or on a locked one, is read only in the dialog, and the row says why. A user parameter feeding such a dimension still drives it: that changes a value, not the object.

## 5. Application flow

**Design mode** [ref]: top bar shows the Solid tab. Browser tree lists `Origin` and `Sketches`.
`Create Sketch` shows an isometric picker of the three origin planes; clicking one creates `Sketch N`
and enters **Sketch mode**. Right-click sketch node: Edit Sketch, Export DXF, Show Dimensions,
Delete, rename. Visibility eye toggles the sketch. A sketch is shown with the browser icon state:
red lock when fully constrained [ref]. [adapt] Design mode shows, in plan, what the plane last looked
at shows of each visible sketch (as in Sketch mode, below); the Orbit view shows them all in 3D.

**3D mode** [user]. *What a sketch sees.* On plane P a sketch shows, of every other visible sketch,
the points that lie on P and the curves lying wholly in P, within 1e-6 mm (`src/model/seen.ts`). From a
sketch on P itself that is everything, in this sketch's coordinates, mirrored if it faces the other way
(arcs then run the other way round, and text is left out). From a sketch on another plane it is the lines
with both ends on P, where the two planes meet, and its points on P. All of it is template geometry under
the rules of section 9: picked by Project, snapped to, referenced by constraint and dimension picks
(projected first, linked), never edited. Layer visibility, locking, Show Constrained Lines and the
construction toggles mean what they always do. Exports and Print stay in each sketch's own coordinates.

*Fold.* With exactly one straight line selected (a line of the sketch of any line type, a projected line,
or an origin axis) and the Select tool idle, the arrow keys fold the sketch plane a quarter turn about it.
The arrow is the way the camera moves. A line running across the screen takes Up and Down, one running
up it Left and Right; a slanted one the pair nearer square to it, and one at exactly 45 degrees Up and
Down. The other pair does nothing. Up: the camera swings up over the line and looks down onto the new
plane, which holds the line and whose normal is the old plane's direction square to the line on the
arrow's side. The camera's axes turn with it, so the line stays where it was on screen and the old plane
lands edge-on along it; the new sketch's u and v are the screen's right and up, so nothing is rolled, and
its origin is the foot of the world origin on the plane. A visible sketch already on that plane facing
that way is reopened instead, the swing ending with a short roll that stands its y axis up; one facing
the other way is not, and a new sketch is made, named as Create Sketch names it, in one undoable step.
The line comes into the sketch as a linked projection, as Project makes it, and is selected, so the
opposite arrow swings straight back; its source leaving the plane makes it a lost projection. An axis
comes in as the sketch's own projected axis when it is one, else as a fixed construction line. Anything
else selected: the arrows do nothing, and the status line says why. In a text field, a dialog or a menu
the arrows are theirs. Switching sketches ends the open tool as Edit Sketch does.

*Other planes.* In Sketch mode, where the plane of each other visible sketch meets this one is drawn as
an infinite line right across the view, under the geometry, in its own colour (`--c-plane-line`, a cyan,
apart from the axes, construction and the layer colours). One line per plane: sketches sharing a plane,
facing either way, share it; a parallel plane has none. With Select idle, hovering it lights it and the
tip by the cursor names the sketch or sketches on it; clicking it swings the camera about it, by the angle
between the planes, onto that sketch and edits it, ending with a roll that stands its y axis up. Several
on one plane: the click opens the marking menu's list of their names to pick from. It is not a hinge, a
snap target, a Project source or anything that selects, and geometry under it, the hinge's own copy
included, takes the click; it does take the click from an origin axis it runs along. Sketch Palette >
Other Planes (on by default, kept with the other options) hides it. The Orbit view does not draw it.

*Swing.* 340 ms, plus 140 ms for a roll; orthographic; at once under `prefers-reduced-motion`. Input
waits until it lands. Meanwhile every visible sketch is drawn through its frame: points go through the
camera one by one and are stroked on screen, so line weights hold and circles seen at a slant are
ellipses. The origin planes and axes are drawn faint.

*Orbit view* (`V`, or the button beside Home View). Every visible sketch in 3D, orthographic, with the
origin planes and X, Y, Z axes faint. Drag orbits (across turns about Z, up and down tilts); the wheel
zooms at the cursor and a two-finger drag or middle drag pans, as in plan. Home View and `F6` go to the
isometric Home, from front right above (+X, -Y, +Z), round everything shown. Clicking a sketch's
geometry, or its row in the browser, edits it, the camera swinging round to face it (fitted to it, or
the view it was left in). `V` again or `Esc` goes back to the sketch it was opened from, facing it as it
was. Tools and most keys wait while it is open; Undo, Redo, Save, Open, New, Print still work.

**Sketch mode** [ref]: contextual Sketch tab highlighted, with panels Create, Modify, Constraints,
Select, Finish Sketch (green check). The Sketch Palette floats top right. Finish Sketch appears on
toolbar and palette. Finishing a sketch returns to Design mode.

Start the tool loop: `select` is the default tool. Every tool ends back in `select`.

The three arrive as `wheel` events and are told apart in `src/app/wheel.ts` from what the event
carries. `ctrlKey` is a pinch (or Ctrl and a wheel). A `deltaMode` of lines or pages is a wheel. A

decision is made once per burst of events, which ends after 120 ms of quiet, so a gesture never flips
between pan and zoom; when it cannot be made it is a wheel and zooms. The canvas always cancels the
event, and `overscroll-behavior: none` keeps a swipe that reaches the page from going Back.

### Min Distance on the status bar [user]

An owner addition, not in `reference/`. With exactly two objects selected in a sketch, the bottom bar
shows `Min Distance: 12.34 mm` between the prompt and the sketch state, in the design's units through
`formatValue`, as the same bar already writes a length. The bar is the width of the window: the solve-time readout goes first, then the coordinates, the prompt, the note and the sketch state give way, and the readout does not. For any other number of selected objects, a
selection with something that has no drawn shape in it, and in design mode, it is empty. It does not
replace the prompt or the note: it sits with them.

What is measured is the geometry as drawn. A line is its segment, an arc only its sweep (the nearer end
point when the full circle is nearer), a circle its rim, an ellipse, spline or conic its curve. A point is
any point: sketch points, the origin, and the end points, centres and fit points a curve owns. The gap is
0 where two objects touch or cross, a point on a curve is 0, a line inside a circle gives the gap to the
rim, and concentric circles give the difference of their radii. The two-object readout is of what is selected, and selection is a pick
on the active layer, so another layer and a locked one are not measured that way: the selection rules are not changed. The Measure tool
below reads the same number for objects on any layer.
Text, dimensions, constraints, features and the axes have no drawn shape in this sense: with one of them
among the two, there is no readout.

`src/geom/min-distance.ts` is the pure maths. Points, lines, arcs and circles are closed forms: a list of
candidate pairs (a crossing, the end points, the normal through an arc's centre, the line of centres of
two arcs), each a real pair of points on the two objects, so the smallest is exact. Ellipses, splines and
conics take the app's own flattening as a seed, with a chord error that follows the size of the curve, every
pair of sample segments within a few chord errors of the nearest as a start, the existing `intersect` for
crossings, Newton on the two parameters with the ends held, and a compass search on the winner. A degree 1
control spline is a polyline, read segment by segment. Accuracy is in `docs/AUDIT.md`.

When it is worked out: `App.minDistance()` keeps its last answer against `shapeKey` of the two objects,
which is every point position and parameter the measure reads, so it runs only when exactly two are
selected and only when one of them changed: not on a mouse move, not on a drag of something else, and
once per frame at most during a drag, because `StatusBar.refreshMinDistance` is called from the frame
and from the selection, doc, mode and status events. An empty readout still holds its width (`22ch`,
tabular figures, `--ink`) so the bar does not shift when a value appears; in design mode it is hidden.

**Measure** (`tools/measure.ts`, Inspect panel, `I`). The same readout for objects the selection cannot take. The tool picks with
`ctx.hit(screen, { anyLayer: true })`, which drops only the active-layer rule: what is shown is pickable, locked layers included, and a
hidden layer, a hidden construction line, the axes and text are not. The picks go to `ctx.measure(ids)`, which lights them (the same lit set a dialog's picks use) and hands them to `App.minDistance()`
in place of the selection for as long as the tool runs; the selection is never touched, so the selection rules and the single-layer editing rule are as they were. Two picks give
`Min Distance: ...` through `minDistanceBetween` and `formatValue`; a third starts over with itself; picking the same object twice is
refused with a note; Esc leaves, which clears the lit pair and the readout. The tool is `readOnly` in its meta, so a locked active layer
does not disable it, it makes no commit and so no Undo step, and it adds no Feature Options row to the Sketch Palette.

### Time to solve on the status bar [user]

An owner addition, not in `reference/`. Next to the sketch state ("Under-Constrained", "Constrained",
"Over-Constrained") the bottom bar shows the time of the last solve of the open sketch, `Solve 3.2 ms`:
one decimal under 100 ms, whole milliseconds from 100, and `Solve <0.1 ms` for a time too short to show a
tenth. The order along the bar is prompt, note, Min Distance, time to solve, sketch state, coordinates.

What it measures is main-thread wall time (`performance.now()`) for one whole request as the user met it.
`solveSketch` in `src/solver/bridge.ts` is the one place a solve is timed and hands the time back as
`ms`; nothing is timed inside the bridge's seats, walks and fallbacks or in the Rust crate, so every one of
those, and the final `checked` step, is in the time of the one request. A commit is one request however
many times it calls `solveSketch` (a new dimension solves once to measure and again to place): `App.commit`
and Compute Sketch add up their solves per sketch and keep the total, a refused commit included. A drag
step is one solve and replaces the figure, so it follows the drag, at most once per frame. The first look at
a sketch that has not been solved in this session takes a time too. Undo, Redo and a revert solve nothing:
the sketch is read back as saved, so the figure is left as it was, and a sketch with no time yet shows none.
The time is kept per sketch, so another sketch shows its own, and a new, opened or reloaded design starts
without any. It is empty in design mode and with no sketch open.

`StatusBar.refreshSolveTime` runs from the frame, so the DOM is written once per frame at most, and from
the doc, mode and status events. The readout holds its width (`118px` with the bar's gap, tabular figures,
`--ink-2`) when empty, so the bar does not shift as the figure changes. When the bar is too narrow it is
the first to give: it has a flex shrink factor so large that it takes the whole shortfall, bar gap included,
before the prompt or the coordinates lose any, and its wording is hidden by a container query as soon as it
has less than its full width, so a clipped number is never shown. Min Distance does not shrink and has
priority over it. Tested down to 560 px.

### 7a. Theme [user]

File > Theme: System, Light or Dark, with the current one ticked. System is the default, follows
`prefers-color-scheme` and changes live when the OS does. The setting is a preference of the browser:
it lives in `localStorage` under `sketch.theme` (reads and writes are guarded, so storage that throws
only costs the memory of it), and it is not in the saved file, not an undo step and not in history.
`index.html` sets `data-theme` on `<html>` before first paint, so a dark page never flashes light.

One set of colours: `src/ui/tokens.css` holds Light (`:root`) and Dark (`:root[data-theme='dark']`).
The DOM reads them as custom properties, icons included. The canvas reads the `--c-*` ones through
`src/render/palette.ts`, which parses that same file, into `COLORS`; changing the theme swaps those
values in place and repaints in the same task. There is no colour literal in `src/ui`, `src/render`,
`src/tools` or `src/app` outside the file, except the white of `@media print`.

Layer colours stay as the user set them, in the data and in the swatch. On the canvas in Dark, a colour
whose contrast with the canvas is under 3:1 is drawn lighter, keeping its hue and saturation, until it
reaches 3:1 (`legibleOn`); one that already reads is drawn as stored. In Light nothing changes.

SVG, DXF and Print do not know about the theme: `src/io` imports none of it, and the print page is
white whatever the theme. `src/render/palette.test.ts` computes the contrast of every text pair
(at least 4.5:1) and every geometry colour against the canvas (at least 3:1) in Dark.

## 8. Persistence and export

- Autosave `Design` JSON to `localStorage` (debounced), File menu: New, Open (`.sketch.json`, or an `.svg` saved with its data, see
  section 9), Save, Save as SVG, Print, Recover Designs. Save writes `<design name>.sketch.json`; the opened design's name, Save and
  autosave come from it, not from the file's name.
- **Unsaved changes.** The design is dirty after any commit, Undo or Redo since it was last saved, opened or started new (Undo does not
  make it clean again). File > Save and a save of an editable SVG (Save as SVG with "Include editable data" ticked, once the file is
  handed over) clear it; an SVG without the data does not, since it is not the design. A reload keeps the answer: the fingerprint of the
  design last saved is in `sketch.saved`, and a restored autosave is dirty unless it matches. When dirty, File > Open, File > New (and
  the + beside the name) and Recover Designs > Open first show the app's own dialog, Unsaved Changes, with Save (downloads the project
  file, then goes on), Don't Save and Cancel (nothing changes; from Recover Designs it returns there). With nothing unsaved there is no
  prompt. The app takes no file dropped on the window, so there is no drop route; there is no beforeunload prompt either, as the autosave
  keeps the work.
- Reading a design is silent: opening a file or restoring the autosave gives no commit notes, only what the file itself needs saying.
  An error on the way in leaves the app up. **A file that cannot be opened changes nothing**: it is read and validated before any state
  is touched, the new history is built before the swap, and if the swap itself throws part way the design, its Undo and Redo and the
  open sketch are put back as they were, with a note, for a project file and an SVG alike.
- **Rescued autosaves** (`io/rescue.ts`). An autosave that cannot be restored, thrown or unreadable, is copied into a list of at most
  five, newest first, each under its own key `sketch.rescued.<id>` with an index `sketch.rescued` holding its time and size. A copy is
  never overwritten; the same text is not kept twice. With five held, the oldest goes only if the new one then fits, and comes back if
  it does not. A full store keeps everything it has and says so; the original autosave is then still the only copy, and nothing is saved
  over it. An older `sketch.autosave.rescued` is moved into the list, as its oldest, on boot, and removed once it is there. The boot
  starts an empty design and shows a note on the canvas with a button to File > Recover Designs..., a dialog listing each copy with
  Open, Download (the raw text, whatever it is) and Delete, and an empty state. Open goes through the Unsaved Changes prompt; a copy that
  does not open says so, keeps the design as it was and the copy where it is.
- History is snapshot based: one undo step per committed command, not per drag frame. Cancel in Change Parameters goes back to the design
  as the dialog found it and leaves no step.
- DXF [ref]: browser node right-click → Export DXF dialog: unit (default design units), Points,
  Projected Geometry, Construction Geometry checkboxes, then download. Write R12-compatible ASCII
  LINE, CIRCLE, ARC, POINT, POLYLINE (for splines, ellipses, conics, exploded text). Must import
  cleanly into any DXF reader.

## 9. Layers, SVG and printing [user]

**Model.** `Design.layers` (list order; the top of the list is drawn last), `Design.activeLayer`, design
version 2. Curves carry `layer`; a curve's points follow it; a point with no curve has its own `layer`.
Layers span sketches. Version 1 files migrate onto a default "Layer 1", validated in `io/project.ts`.
Every layer change is undoable and saved with the design. `src/model/layers.ts` holds membership and
the solve plan; `src/ui/layers.ts` is the panel: add, rename, colour, eye, lock, drag to reorder,
delete (geometry goes to the layer below; the bottom layer hands up; the last cannot go), click to
activate. Right-click Move to Layer takes the selection. A hidden layer cannot be the active one:
hiding the active layer is refused and activating a hidden layer shows it.

**Editing.** Only the active layer can be edited. Any other is read-only template geometry: clicks
pass through it, and window, crossing, Select All, chain select and tool picks ignore it. It can be
snapped to, and it cuts Trim and stops Extend. Lock also protects the active layer: selection,
editing and drawing are blocked with a message, and snapping to it still works. Locked layers print
and export. A hidden layer is not drawn, hit, snapped or cut against and is left out of export and
print, but stays in the solver. AutoConstrain, profiles and Find Under-Constrained see the active
layer only.

**Colour.** Lines are the layer colour at the existing styles. Show Constrained Lines (on by default):
the active layer has Fusion status colours, glyphs, dimensions and free-end dots, and every other layer
is plain. Off: every layer is its layer colour, and the active layer keeps its glyphs, dimensions and
dots under their own palette rows. Selection, hover and red always show. Construction: Active Layer
Only (on by default) hides construction and centerlines on other layers, which then do not snap either.
A single layer at the defaults looks as it did before layers.

**Cross-layer constraints.** Constraint tools and Sketch Dimension take another layer as a reference
pick, and hover it as valid only there. At least one object must be on the active layer. Whichever
order they were picked in, the active-layer object moves. `dependentLayer` on a constraint or dimension
names the side that follows and owns it; `stampCrossLayer` sets it for everything a commit made,
inference included. Cross-layer constraints have a distinct glyph, shown on the owner only, and a
point-to-point join shows one too, unlike a join within a layer, or it could not be deleted.

**Solving.** `planFreeze`: the active layer and the transitive closure of its dependents may move; all
else goes to the solver as hard `fixed`, since `hold` is only a wish. A locked dependent stops the
closure: its link is left out of that solve, or it would pin the reference, then checked with every
point fixed, and goes red with a message; unlocking lets it follow. Dependents and the moved layer
solve together, so a dependent pinned to a frozen layer can limit how far its reference moves. A
dimension whose value changed moves its own layer. Status (dof, colours, the Status line) comes
from a second, unfrozen solve that writes nothing, so a lock can never make a sketch look constrained.
Deleting a referenced object removes the constraint with a message; the other side stays put.

**Save as SVG** (`io/svg.ts`; File menu, sketch right-click). Options: points, projected, construction
(which includes centerlines), include dimensions (off). Constraint glyphs are never included. Under "Include editable data" a line
says what the file will carry beyond the drawing, with real counts, as the options stand: `Includes 2 hidden layers and 14 construction
lines.` It counts the layers that are hidden, the construction lines (and other construction curves) of the whole design that the file
does not draw (all of them unless Construction Geometry is ticked, and always those on a hidden layer), and the sketches of the design
that are not in this export. With the data unticked it says `No editable data: the file holds only what is drawn.`, and the file then has
no `<metadata>`, no hidden layer and no construction that was not asked for.
`width`/`height` in mm with a matching viewBox and Y negated, so 1 unit is 1 mm. `line`, `circle`,
`ellipse` and `A` paths; splines and conics as cubic Béziers within 0.01 mm, exact for cubic spans,
with a polyline fallback. Dashes preserved. One named `<g>` per visible layer, bottom of the list first,
in layer colours. Text as outlined paths; dimension values stay `<text>`.

**Editable SVG** (`io/svg-data.ts`). The dialog's "Include editable data" (ticked by default; it says the data holds the whole design,
including hidden layers and construction geometry) puts the design in `<metadata>` after `<desc>`. Nothing drawn changes: the same
elements, with or without it. The design is the project file's own text, `serialize(design)`, held as base64 of its UTF-8 so that no XML
tool can change a character of it (`]]>`, `<`, `&`, quotes, any script, whitespace between elements):

```xml
<metadata>
  <sketch:design xmlns:sketch="urn:sketch-cad:design" format="1" encoding="base64" bytes="10394" crc32="1a2b3c4d">eyJ2ZXJzaW9uIjoy...</sketch:design>
</metadata>
```

`format` is the version of this wrapper; the design inside keeps its own `version`. `bytes` and `crc32` (of the UTF-8 JSON) are checked
before anything is read, and whitespace in the text is ignored. It is always the whole design: every sketch on every plane, whatever the
export shows, hidden layers and construction included. File > Open (and so every route that opens a project file: Open, Recover Designs > Open; the app has no
drag and drop) takes `.svg` as well as `.json`: a file named `.svg`, or one that starts with `<`, is read as SVG, anything else as
a project. The file is parsed with `DOMParser` as `image/svg+xml`, which runs nothing and fetches nothing, only the data element's text is
taken, and nothing of the file is put in the page; a file that declares XML entities is refused. The JSON then goes through `deserialize`
exactly as a project file does (version 1 migrates, a design from a newer app is refused), so a bad design is a message and the open
design is left alone. Each of these gives a plain message and changes nothing: not an SVG, no data ("no editable data", also for an SVG
from anywhere else: there is no import of foreign geometry), cut short, damaged (checksum, length, characters), a newer format or design
version, an unknown encoding, a design that does not validate. Edits made to the SVG elsewhere are not read back: the embedded design is
what opens. Undo history is not stored, in an SVG or in a project file, so it starts empty after an open. A program that writes its own
SVG (`rsvg-convert -f svg` was tried) can drop the metadata; the result then opens only to say it has no data. Sending the file sends the
whole design: untick the option to share the drawing alone.

**DXF.** With a design, each visible layer is a named R12 layer (illegal characters become `_`) in the
nearest ACI colour. A layer's construction, projected geometry and points go on `<name>_CONSTRUCTION`,
`<name>_PROJECTED` and `<name>_POINTS`.

**Print 1:1** (`io/print.ts`, `tools/print.ts`; File menu, Cmd/Ctrl+P). A4, A3, A2, Letter, Tabloid;
orientation; one margin for all sides; a preview of the placement. Pages are SVG in real `mm` under
`@page`, sent through `window.print`. What is bigger than the drawing area tiles with a 10 mm overlap,
alignment marks along the seams and page labels. Every page has a 100 mm scale bar in a 13 mm footer.
Browsers cannot force the printer's scale, so the dialog says to choose 100% or Actual size, not Fit to
page, and to check the bar with a ruler. Construction, projected geometry and points follow the
palette; dimensions are a dialog option. Both exports and print take the open sketch, or from the File
menu in design mode every shown sketch in the frame looked at, each in its own coordinates.
